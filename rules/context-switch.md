# 多项目上下文切换管理

## 策略 1：CLAUDE.md 做项目宪法

- 每个项目根目录必须有 `CLAUDE.md`
- 包含：项目定位、核心架构决策、技术约束、当前工作重点
- 切换项目时**先读这个文件，30 秒恢复上下文**

### CLAUDE.md 应包含的内容

```markdown
# [项目名称] 项目规则

## 项目定位
- 项目是什么
- 解决什么问题
- 目标用户

## 核心架构决策
- 为什么这样架构
- 关键技术选型
- 重要的设计决策

## 技术约束
- 禁止使用的技术
- 必须遵循的规范
- 性能要求

## 当前工作重点
- 正在开发的功能
- 接下来要做什么
- 已知的待解决问题
```

## 策略 2：离开前记录"下一步"

切换项目前，必须完成以下记录：

1. **在 task list 记录进度**：当前完成到什么程度
2. **明确"下一步"**：具体要做什么，精确到可以立刻开始
3. **记录上下文**：关键的中间状态、需要注意的点

### 示例

```
# QREquip 进度记录 - 2026-05-01

## 已完成
- 设备列表页完成
- 设备新增对话框完成

## 下一步
- 设备编辑对话框（已在 device/index.vue 中预留了 AddDeviceDialog）
- 需要对接 POST /api/devices 接口

## 注意事项
- 设备状态必须从 sys_dict 动态获取，已在 sys_dict.go 中实现
- 二维码生成依赖 qrcode 包，已测试通过
```

## 策略 3：单一活跃项目原则

- 同时处于**活跃开发**的项目不超过 **2 个**
- 活跃项目：正在新功能开发、重大重构
- 其他项目：只做维护（bugfix、小优化）

### 如何判断

| 状态 | 说明 | 操作 |
|------|------|------|
| 活跃 | 新功能开发中 | 全力推进 |
| 维护 | bugfix、小优化 | 保持关注 |
| 搁置 | 暂时不动 | 归档，等待下一次活跃窗口 |

## 切换后的恢复流程

当切换回一个项目时：

1. 读取项目 `CLAUDE.md`（30 秒恢复上下文）
2. 查看 task list 中的"下一步"
3. 如有需要，向 AI 描述当前状态："我在做 XXX，刚完成 YYY，现在要做 ZZZ"
4. AI 会帮你快速恢复上下文

## 多项目场景示例

```
项目 A（活跃）：QREquip - 设备管理模块开发中
项目 B（活跃）：NexusWeb - 插件系统重构中
项目 C（维护）：旧工具 - 只修 bug

切换时：
A → B：task list 记录 A 的进度，读 B 的 CLAUDE.md
B → A：task list 记录 B 的进度，读 A 的 CLAUDE.md
C → A：直接读 A 的 CLAUDE.md 和 task list
```
