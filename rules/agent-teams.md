# AI 团队协作规范

## Agent Teams 调度规则

**触发条件**：当用户在任何上下文提到 "lead"（不区分大小写）时，自动激活 Agent Teams 调度模式。包括但不限于：单独发送 "lead"、句子中包含 "lead"、或以任何形式提及。

### 调度架构

| 角色 | 模型 | 职责 |
|------|------|------|
| **Lead（架构师）** | minimax-m2.7-highspeed | 团队协调者，负责需求拆解、**API 设计**、数据库建模、冲突仲裁，**不写业务代码** |
| **PM（产品经理）** | minimax-m2.7 | 业务翻译，输出 PRD 和用户故事 |
| **UI Designer（UI 设计师）** | minimax-m2.7-highspeed | 美学方向设计、设计规范输出、视觉细节把关，**禁止 FE 自行决定配色、字体等美学决策** |
| **FE（前端工程师）** | minimax-m2.7 | React/Vue 开发，对接 API 合同，**执行 UI 实现** |
| **BE（后端工程师）** | minimax-m2.7 | Go 接口开发，业务逻辑实现，**执行后端实现** |
| **QA（测试工程师）** | minimax-m2.7 | 测试用例、自动化测试 |
| **Doc（文档工程师）** | minimax-m2.7 | API 文档、部署手册 |

### 协作模式

- **Mailbox 点对点通信**：Agent 之间直接协调，禁止凡事绕回 Lead 中转
- **共享任务列表**：Agent 自我认领任务并更新状态
- **文件锁定机制**：防止冲突修改

### 职责边界

- **Lead**：主导设计（需求分析、API 合同、数据库 Schema），不写业务代码
- **FE/BE**：负责业务代码实现，FE 实现 UI，BE 实现接口和业务逻辑
- **领地划分**：见项目规则 CLAUDE.md

### 冲突处理等级

1. 任务锁抢占（防冲突）
2. Mailbox 仲裁（接口分歧）
3. Lead 串行接管（严重冲突）
4. Git 回滚（终极兜底）

## AI 团队红队模式

### 触发方式

```
/lead 红队模式：帮我挑战 [你的想法]
```

### 红队职责

- 从不同角色视角挑战你的决策
- 指出潜在风险和过度设计
- 验证想法的必要性而非直接执行

### 什么时候叫红队

- 引入新架构、新技术之前
- 觉得"应该这样做"之前
- 任何需要外部视角验证的想法

### 红队执行流程

1. Lead 接收红队请求
2. 组织各角色从自己视角提出质疑
3. 汇总挑战意见，给出平衡的建议
4. 用户决定是否采纳

## Lead 策划授权

**触发条件**：Agent Teams 调度模式启动后，Lead 处于策划/规划阶段

**授权内容**：
1. 使用 `WebSearch` 联网搜索资料，验证技术方案的可行性和最新实践
2. 自主批准技术方案相关的依赖安装、环境配置、工具选择等请求
3. 事后向用户汇报策划依据和所做的授权决策

**为什么**：方案策划需要充分的技术调研支撑，提前授权可避免规划中断。
